# HAL v2 Direct-Fidelity Ready MVM Specification

**Medium:** WEB_PRODUCT / independent offline HTML demonstration. **Human-facing core mechanism:** switching between two specialist domain bundles under the same shell, with both developer and consumer access paths.

## Eight operational views
1. Welcome: compare two pathways, visible objective and magic-moment.
2. Developer: selected domain-specific README, actual ZIP and CLI instructions.
3. Key Academy: four knowledge-check missions, score and curated provider links.
4. Activation: simulated capability preflight, blocked incompatible managed-agent port; no key input.
5. Domain Studio: real Research math or Returns triage with validation, export and clearly simulated explanation.
6. Capability Matrix: per-feature typed port bindings; local JSON inspection (no code execution); diagnostics export.
7. Trust & Recovery: explicit REAL/SIMULATED/ASSUMED/OUT_OF_SCOPE and disconnection.
8. Human Gate: measured interaction checkpoint progression, qualitative scores, export UAT JSON.

## Meaningful interaction/engagement contract
- Affordances (sample >12): A/B selection, domain selection, ZIP download, README acknowledgment, command copy, manifest export, 4 interactive lesson answer buttons, lesson prev/next, provider selector, preflight, activation, calculation, triage, Markdown export, JSON receipt export, simulated insight, feature matrix, JSON import drag/drop, diagnostics export, disconnect, negative test, UAT ratings, UAT export, reset.
- Types: navigation, dropdown, number input, quiz choice, download, drag/drop file inspection, enable/disable gated actions, feedback text.
- 3 gamified mechanics: 4-question Academy progression; 5 mission progress flags; two-domain magic moment status; optionally an explanatory readiness matrix.
- 2 feedback loops: learning answer correctness; domain tool result & invalid-input recovery.
- Direct manipulation equivalent: drag/drop manifest JSON into inspector.
- 4+ exports: developer ZIP, manifest JSON, Markdown domain report, run receipt JSON, compatibility diagnostics, Human UAT JSON, journey log.
- Negative/recovery: unsupported `manus` direct model preflight, revenue=0 invalid, days negative, disconnection.
- Personalization: domain switch updates README/feature registry/tools/UI in the same shell; session-only state intentionally not misleading as memory.

## Truth ledger
REAL: client-side deterministic specialist functions, genuine packaged CLI ZIPs, navigation, scoring, manifest file inspection and exports. SIMULATED: model preflight and explanation. ASSUMED: native secret broker and future actual LLM model. OUT_OF_SCOPE: live credentials, paid calls, real data integrations, autonomous scheduling and GitHub release.

## Testability
Smoke test scripts must verify seed outputs: Research 1500/900→600/40%, Returns sealed/yes/5→STANDARD_RETURN; negatives; 4 lessons complete; 2 ZIP integrity; mode activation simulated; provider mismatch blocks; no API key input fields or outbound fetch. Human should actually run walkthrough and choose gate later.
