# Truth, conflicts, privacy and quality gates

## Seven provenance statuses
`OBSERVED` (verified in attached source), `STAKEHOLDER_CLAIM`, `PROPOSAL`, `ASSUMPTION`, `ESTIMATE`, `SUPPLIER_QUOTE`, `VERIFIED_TEST`. Never convert between states without evidence. A well-organized proposal is not empirical evidence that a solution works.

## Version conflicts
The references capture changing scopes and budgets. Some early PRD material uses a fixed one-package delivery framing; later project positioning narrows to a first-phase MVP. Several historical budget examples use differing totals, currencies and inclusions. Retain all versions with date/source. For a NEW PRD, select a decision-appropriate proposal with a rationale; never average contradictory prices or quietly choose the larger budget.

## Data confidentiality
Historical documents include internal organization details and even credential-like strings. Do not copy credentials, links with access codes, unredacted personally identifiable information or proprietary customer data into reusable templates or public skill files. The shipped ledger records source positions and hashes, not source paragraphs.

## Extraction caveats
PDF text blocks may split sentences across visual columns; Slides can contain grouped text, images with unreadable lettering, tables and decorative content. Excel has multiple reviewed versions; the second is NOT independent confirmation. A text unit mapped to an operator is a **proposed conversion**, not a signed semantic audit. Every LOW_REVIEW unit needs a human check before claiming word-level certified coverage. See the corresponding ledger and visual source map.

## Hard blocker rules
Do not finalize quantitative cost, contract, permissions or medical/legal/financial business claims if missing essential decision-grade facts. It is acceptable to deliver the decision-ready PRD with an explicit OPEN blocker, scenario calculation and exact information request, rather than filling with invented numbers.

## PRD compiler sanity checks
- Every section proves its relevance to the Need or says N/A.
- Every feature carries acceptance and a boundary.
- Every architecture layer has explicit interfaces/data path/trust scope.
- Every claim has evidence provenance and is correctly classified.
- Every timeline has owner/dependency/exit condition.
- Every supplier fee has status, currency, unit, interval and source.
- Every numerical target can be measured against a baseline.
- Every irreversible external action identifies human authorization.
- Every page diagram's arrows correspond to testable information/control flow, not merely decorative elements.
