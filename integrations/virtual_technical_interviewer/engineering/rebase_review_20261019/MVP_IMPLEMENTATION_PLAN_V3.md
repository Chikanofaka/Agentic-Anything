# TIA v3 实施计划与工作包

日期：2026-10-19。基线：`53188034400be6c534d2ded56a9386ea55d6ad0e` 的完整 v3、原始用户材料和已接受修正。本文是工程提案，替代上一轮 Rapid 计划；尚未进入新 TIA 代码实现。来源差异见 [迁移回执](BASELINE_DELTA_RECEIPT.md)。

## 1. 完整范围与首个真实闭环

当前范围保留全部 28 项功能要求和 12 项 P0 Communication 要求，不能把整份产品愿景缩写成一次静态聊天演示。

| 层级 | v3 功能要求 | 本计划中的处理 |
|---|---|---|
| M0 | FR-01..14、FR-25、FR-27、FR-28，共 17 项 | 首个真实、本地、无模型闭环的工程验收范围 |
| M1 | FR-15..19、FR-26，共 6 项 | 保留待实现，包括受控模型、Python、安全扩展、完整 UI 与人工复核的复杂度判断 |
| Future | FR-20..24，共 5 项 | 保留语音、多格式、提醒、商业化、内容扩展；不纳入本轮成本或授权 |
| 横贯 P0 | COM-FR-001..012 | 在 M0 各阶段接入观察、行为、证据、复核及训练，不等到 UI 完成后才加评分标签 |

建议首个闭环：配置与同意 → 面试官开场/澄清 → 候选人计划 → 真实受限 SQL 提交和测试 → 两轮以上反馈与恢复 → 结束并锁定事实 → 证据化双评分 → 可解释复核/申诉 → 单项 Trainer drill → 新会话中的留出可比题。真实 SQL 执行是 M0 的条件；人工评估或脚本面试官可以明确标记为离线模式，但不能用预制测试结果冒充执行器。

先选一个 SQL 题族打通，随后按覆盖需要加入稳定排序/NULL、去重、JOIN 基数诊断。首题族、数据库方言与题目许可尚待选择。初始只读模式不支持 DELETE；后续若引入删除题，必须另建受限可写契约，不能静默放开初始执行器。

## 2. P0 Communication 的可交付定义

每个重要回合保留 actor、stage、time、event ID、所关联的计划/代码/测试版本以及观察机会。具体观察覆盖：目标澄清、计划与取舍、进展和证据、知识缺口与合规请求、反馈后的行动、诚实收尾。done / proved / gap / independent attempt / focused request / feedback-to-action 是可用的分析字段，不要求用户每轮照读六句模板。

| 行为链 | 最小可审阅证据 | 必须阻止的误判 |
|---|---|---|
| 澄清 → 计划 | 引用真实发言，关联题意、假设与后续实现 | 把索要答案当澄清；凭流利度生成技术分 |
| 卡住 → 诊断 | 区分概念已知、语法回忆、API 缺口、结构误解；允许弃权 | 把一律“不会”或一律“接近完成”写成事实 |
| 求助 → 回复/拒绝 | 请求范围、许可版本、实际披露的帮助级别 | 用说服力换取越权提示；奖励获得提示本身 |
| 理解 → 实施 → 验证 | AH/BH/CH/DH/EH 分支及第二/第三步行动 | “I understand” 自动记 coachability 或测试成功 |
| 失败 → 再决策 | 4/20 排序遗漏与 4/20 结构缺口的不同诊断 | 把测试通过比例等同任务完成百分比 |
| 结束 → 复核 → 训练 | 双轴各自证据、覆盖度、争议及 drill 标签 | 缺证据按 0；模型直接改分；训练反写面试历史 |

Technical 和 Communication 独立保存、独立计算、独立展示。同一事件可以支持两个具有不同理由的判断，但不能把同一个印象复制成两项成绩。60/40 是用户当前假设；v3 的 11 个子权重和 0–4 锚点可作为明确标记的 fixture，不代表已批准生产评分。Bonus 10–15 假设默认禁用。

## 6. 工期、成本与风险

旧 15.5–27.5 人日估算建立在较窄的 Rapid 范围上，**不沿用为 v3 交付承诺**。新增申诉、数据权利、完整后续回合、冷用户手册、留出题与全阶段 Communication 会增加工程和校准工作。先用 WP1 的权限/持久化 spike 与 WP2 的真实 SQL 安全 spike 获取实际成本，再按 WP 拆估；目前估算为 TBD，而非伪精确的新总数。

离线 M0 不依赖付费 API。后续预算应按“会话数 × 各角色调用次数 × 实测输入/输出量 × 当时经核验费率 + 存储/语音/运行成本”计算；本轮不选择供应商、不调用模型或编造报价。人工评估时间应单独记账。

最高工程风险是 Witness 专属 host 被误当通用接口、完整 snapshot 泄露封闭资料、SQL 只靠字符串过滤、模型回滚丢失候选人已提交行动、以及重复请求导致重复评分。最高产品风险是把语义判断的稳定算术当作已验证能力测量，或把同题熟悉度当迁移。逐项对应验收矩阵，失败须留在结果中。
