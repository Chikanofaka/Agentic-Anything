# WTL-029 v0.3 implementation decisions

Scope: first-playable local Mac detective game, built on the existing HAL architecture. Started 2026-10-16; resumed 2026-10-17, Asia/Shanghai. The supplied integrated implementation prompt and the user's six workstreams govern this increment. Historical proposals inside story files are authoring data, not new permission gates.

1. **Canonical authoring:** edit the five named files in `integrations/witness_loop/source/`. The duplicate `WTL-029_Witness_Loop_v0.1/` copies were byte-identical at sprint start and remain a reference, not a runtime input. Compiler output reports duplicate drift explicitly. Original ten-file v0.1 material is preserved byte-for-byte in `integrations/witness_loop/reference_v01/`, recovered from local commit `b234d98`; it matches the original source hashes. User-authored updates were not overwritten.
2. **Reviewed compilation:** a build-time compiler extracts named sections into `witness_character.json`, with version, source hashes and projection digest. Changing a supported personality section changes the built model context after rebuilding. Unknown Markdown does not become instructions, a file include or executable code. Canonical identity changes require code review. Only the safe case-brief section is projected; raw director story files are excluded from app resources and developer UI. Trusted local source editing still requires semantic review; filters do not solve arbitrary prompt injection.
3. **Identity and knowledge:** Lin Wu is an adult anxious, protective, restrained, morally conflicted dispatcher. Her younger brother Lin Yu exists even when she conceals his involvement. Stable identity, private knowledge, uncertain/unknown facts, authorized admissions, player observations and session memory remain separate. The limited model projection never receives the complete director story. The public local source code is not cryptographically secret.
4. **Two calls:** the nervous interrupted outgoing call near the investigator's arrival is `overheard_call` / `call_recent`; the earlier incoming 00:17 call is `call_0017`. Neither the stopped clock nor the recent call proves the train's departure time. This sprint does not invent an authenticated 00:24 operating record.
5. **Versioned experience:** new sessions use `witness-state/v2`, with a separate experience phase and existing `scene` 1–3. Brief → narrator → empty observation scene → explicit approach → first NPC caption → Continue → player input → pending → NPC caption. There is no unversioned `scene=0`. Local state decides progression; showing art does not collect evidence.
6. **Evidence:** visible, inspected, authenticated, interpreted and linked are distinct flags with provenance. Authentication of a physical clock reading means the inspected reading is established; it does not authenticate a timetable. Fabric ownership requires testimony after inspection. A ticket's appearance does not establish whether Zhou boarded. Revisit missed objects later; entering Scene 2 grants no new physical clue in fresh v2 games.
7. **Deduction and endings:** retain the reviewed clock/call relationship and three deterministic outcomes for the MVP. It is a working investigative relationship supported by testimony, not an airtight physical proof of departure time or the whole director conspiracy. Outcomes are scoped to the available case evidence. No model text sets a verdict or silently adds a clue.
8. **Actions and language:** six case actions, free conversational turns and 20 provider requests are separate counters. Preview known case questions before confirmation. If a model proposes a case interpretation for a follow-up, require confirmation before changing the case; cache the proposal for the same text to avoid another classifier request. Mandarin/English preference changes language, never truth. A model request may already have consumed one request when a semantic proposal needs confirmation.
9. **Dialogue validation:** testable identity denial, known unauthorized disclosures, merged calls, unsupported world claims and obvious language mismatch are checked before storing dialogue. Rejected model prose is replaced by an authorized contextual fallback and its reason is recorded. Receipt mode `LIVE_MODEL_REJECTED_FALLBACK` distinguishes used provider requests from the replacement text. Pattern checks remain incomplete; live persona quality and adversarial paraphrases require human UAT.
10. **Non-destructive migration:** `hal-session/v2` is saved to `session-v2.json`. A recognized valid `session.json` v1 record is copied forward with an explicit migration marker; the original is untouched. Old clock and Scene 2 ticket acquisitions are labeled `LEGACY_V1_ACQUIRED`, not newly inspected. Existing endings/progress/history are preserved. Corrupt or unsupported saves fail closed. Clearing the active case leaves legacy backup/export files intact and says so.
11. **Art and packaging:** use the same locally bundled station composition for empty/witness phases, a separate anxious anime sprite, exact SVG clock/ticket and inspectable details. Reference images are local-only and excluded from source delivery; [asset provenance](../integrations/witness_loop/ASSET_PROVENANCE.md) identifies generated and authored artwork. The build creates fresh resources, includes compiled context/art hashes and excludes raw story Markdown. Native-only credentials, fixed OpenAI endpoint and CSP remain intact.
12. **Human Gate:** no live paid inference, secret access, publication, commit/push or player-save deletion during engineering. Deliver the rebuilt app, actual screenshots, automated evidence and remaining UAT for human review. This is an unsigned development app tied to this checkout and its Python runtime, not a portable public release.

Acceptance evidence and file changes are recorded in [WTL03_RECEIPT.md](WTL03_RECEIPT.md); [WTL03_UAT.md](WTL03_UAT.md) separates automated/visual checks from human and live-model acceptance.
