## 4. Least invasive implementation shape — proposed, not coded

**A. Curated package and pure domain adapter.** Add `runtime/fixtures/technical_interviewer/` and reviewed `runtime/trusted_adapters/technical_interviewer_*` modules as proposed in v3 §19. Register exact tool and value contracts through the current maps. If adding an `interview_state` capability is useful, it is an explicit additive schema/registry change with regressions. Do not overload `narrative_state` to imply an interview capability or dynamically import a package entrypoint.

**B. Specialist session controller.** Own host clock, configuration snapshot, question/version selection, expected revision, command idempotency, policy-authorized hints, evidence, closure and safe projections. Reuse inspection/validation and reviewed storage primitives; keep domain-specific rules outside the common engine. The existing `InteractiveBinding` cannot by itself satisfy this. Add only a small backward-compatible facade if it saves duplication and preserves Witness behavior; record actual core changes rather than claim a completely unchanged generic host. No facade or registry changes have been made in this task.

**C. Restricted SQL evaluator and question catalog.** Define dialect, output equivalence, NULL/order/duplicate/numeric semantics, accepted alternative solutions, public/hidden disclosures and fixture versions. Restrict to an explicitly reviewed query subset, deny ATTACH/extensions/file access and unsafe statements, enforce resource/result/time limits, and test violations. Use robust engine authorizer/read-only controls rather than a SELECT regex. A subprocess alone is not an OS sandbox. No existing HAL tool engine supplies SQL containment; do not run arbitrary candidate Python in-process. Reference answers and protected tests must not appear in candidate snapshots, model contexts, diagnostic errors or public export paths.

**D. Evidence, assessment and Trainer modules.** Store immutable facts separately from replaceable/provisional interpretations. A candidate action record, disclosure decision, completed test receipt, assessment version and Trainer plan have distinct IDs and commit points. Every reported grade links to observable evidence and its method. Trainer consumes only the approved post-session packet and safe content tags; held-out item answers are not training context.

**E. Specialist interaction surface and later native adaptation.** Start with a usable local text/CLI or modest UI that completes configuration → interview/admin → clarify/plan/execute/test/recovery → close → review/appeal → Trainer drill → fresh retest. A static script showcase is insufficient. Preserve Path A developer assets and Path B consumer experience. Reuse private IPC patterns where appropriate; HTTP is optional and would need an authenticated local boundary. Later provider and voice adapters remain separate gated integrations.

The proposed integration is a new interview product using HAL's reviewed boundaries. It is not a renamed Witness character, a generic chatbot overlay, or a new universal plugin framework. Its eventual result must be shown through a real end-to-end receipt, not inferred from the package being inspectable.

## 5. Trust, evidence and lifecycle details that v3 still needs resolved

1. **Communication quality and technical validity remain separate.** SQL outcomes, granted hint levels, recorded time and score arithmetic can be deterministic. Correct diagnosis, clear explanation, conceptual understanding and unfamiliar-method reasoning require anchored review, uncertainty and evidence. `USER_SAID` never becomes `USER_DEMONSTRATED` merely because structured fields or persuasive language were submitted. C05 follow-through needs a linked changed plan/code/test/diagnostic action; polite agreement alone is insufficient. A technically failing query remains failing even when communication evidence is strong.

2. **Scoring coverage requires a defined calculation contract.** v3 proposes 0–4 anchors and `max_points × anchor/4` for observed dimensions. Report separate earned observed points, available observed points, coverage and missing dimensions; do not quietly treat absence as zero or normalize a selected subset into a certain /100 grade. Keep actual test outcomes outside subjective aggregates. Record assistance before/after, rubric/weight versions, reviewer and dispute state. The experimental 10–15 bonus stays disabled by default under the supplied JSON.

3. **A full interaction turn is a product unit, not necessarily one storage transaction.** v3 §11A describes candidate action → interviewer response → candidate implementation → evidence as a complete turn. Durability should record each authorized material event at its own boundary. A provider failure cancels a pending reply/disclosure, not an already received candidate submission, completed test or elapsed clock. This preserves §17 no-partial-commit semantics without losing evidence that the candidate acted. Late results require explicit cutoff rules.

4. **Clock and recovery are new behavior.** Decide wall versus monotonic markers, pause/restart, device sleep, expiration while a query/model call is running, and whether a late result is retained only as after-deadline evidence. Current Witness action budgets are not an interview timer. Duplicate close/submit needs stable idempotency behavior and a single frozen receipt.

5. **Hashing is not signing or local-user tamper resistance.** v3 J6 mentions a signed session reference, while W06 permits signed or hashed receipts. The current store/receipts are neither a digital-signature infrastructure nor an encrypted vault. A content digest plus host-controlled read-only handoff is a reasonable explicitly labelled M0 proposal; a cryptographic signature requires a separate key/trust design. A local owner can inspect distributed evaluator assets; protect runtime disclosures without claiming examination-grade anti-cheat secrecy.

6. **Retention opt-out and later explanations interact.** v3's `encrypted-local-ref` example is a proposed field value, not implemented encryption. When raw-text retention is disabled, use transient text during the session, consented minimized observations if allowed, and explicit unavailable/deleted evidence states later. Do not preserve raw text inside “summary”, exported receipt, telemetry or model request as a workaround. Missing cited material must reduce reviewability/confidence; avoid unfulfillable promises of permanent exact-span replay after deletion.

7. **Review and training privileges are declarative until enforced.** A new command authorizer must enforce actor, phase, selected consent and disclosure class. Sharing an LLM across Interviewer/Trainer roles is possible, but merely switching prompt labels grants no boundary. The Trainer must not access future sealed items; reviewer overrides append a reasoned version instead of mutating tests or original facts. The meaning of “reviewed session” and whether explicit user acceptance is required remain to be fixed in the protocol.

8. **Developer export and protected evaluation data need separate rules.** v3's package layout can contain question assets, but developer source export, candidate view, active-session export and post-session teaching have different purposes. Explicitly enumerate allowed assets/fields for each. A `question_bank/hidden` folder or runtime `public_view` function does not itself prevent leakage through raw state, source preview or exports.
